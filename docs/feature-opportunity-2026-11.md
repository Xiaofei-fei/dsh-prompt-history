# dsh-prompt-history 功能机会评估（2026-11）

对标 Claude Code / Codex 的输入层能力，结合 DSH 原生能力与插件市场（8281 个插件）的覆盖情况，
回答一个问题：**这个插件接下来加什么功能，需求大且真正有价值。**

数据来源：
- Claude Code 官方 Interactive mode 文档（2026-11 抓取）
- Codex CLI 官方 Slash commands / CLI 文档（v0.143.0）
- `awesome-dsh-plugin.com/plugins.json`（2026-11-01，8281 条，含下载量）
- 本机 DSH 0.2.0-rc.2 客户端包源码 + 运行中页面实测
- 本插件仓库 issue/PR 历史

## 3. 值得做的功能（按 需求 × 价值 ÷ 成本 排序）

### 🥇 1. 草稿历史与找回（Draft vault）

**为什么有价值**
- Claude Code 有"清空后按 ↑ 找回草稿"，Codex 有"↑/↓ 恢复草稿历史"；**DSH 原生只有一份草稿**（实测：刷新后保留 ✓，但没有历史、没有多份、清空即丢）。
- 市场**没有**任何草稿历史插件。
- 长提示词被误清空、或同时在想几个问题，是每天都在发生的真实痛点。

**功能设计**
- 自动快照：草稿停顿 1.5s 且内容变化 ≥20 字时存一份（每会话最多 20 份，localStorage，带时间与首行摘要）。
- 快捷找回：空输入框按 `↑` 若存在更新的草稿快照则优先给"草稿"，再按一次进入提示词历史（两者用不同前缀标识区分）。
- 草稿舱面板：`Ctrl+Shift+D` 打开列表，可预览/恢复/固定/删除，固定项永不淘汰。
- 多槽位：`Ctrl+Alt+1..9` 存/取草稿槽（像编辑器 buffer）。
- 与侧聊联动：`Ctrl+Shift+S` 把当前草稿"停靠"进侧聊，主会话清空。

**成本**：约 250 行 + 3 条 e2e（恢复、淘汰、与历史键互不干扰）。
**风险**：低。只碰我们自己的键链与 localStorage，不触碰宿主的提交路径。

---

### 🥈 2. 发送前的敏感信息守卫（Secret guard）

**为什么有价值**
- 没有任何输入层插件做这件事；而提示词会进入**持久化的会话记录**（还会同步/导出），贴一个 `sk-…` 或私钥就等于泄露。
- `cc-safety-net`（84k）守的是**命令执行**，不是草稿内容。
- 成本极低、感知极强：一个黄色提示条 + 三个按钮（仍然发送 / 自动脱敏 / 打开编辑）。

**功能设计**
- 检测规则（客户端正则 + 熵启发）：OpenAI/Anthropic/DeepSeek key、GitHub token（`ghp_`/`github_pat_`）、
  AWS `AKIA…`、私钥块 `-----BEGIN … PRIVATE KEY-----`、JWT、`password=`/`token=` 赋值、高熵长串。
- 命中后在输入框上方显示："检测到 1 个疑似密钥（sk-…3f9a），会被写入会话记录"。
- 一键脱敏：替换为 `sk-***`（可撤销，保留原值到发送前）。
- 同时**不写入历史环**（避免二次泄露）。
- 复用给"不可见字符/超长粘贴"告警（同一条提示通道）。

**成本**：约 180 行 + 2-3 条 e2e（构造样例、脱敏、不记历史）。
**风险**：低；正则误报需可一键忽略并记住。

---

### 🥉 3. 跨范围提示词搜索（Scope search）

**为什么有价值**
- Claude Code 的 Ctrl+R 可以**循环切换范围**（本会话 → 本项目 → 全部）；我们现在只有本会话。
- 我们已经有全局历史环（200 条）与搜索浮层，**只差范围与预览**。
- `dsh-search-index`（10.8k）证明"搜索"是刚需，但它搜的是会话，不搜提示词。

**功能设计**
- 搜索浮层内 `Ctrl+S` 切换范围：本会话 / 本工作区 / 全部（徽标显示当前范围与条数）。
- 结果行显示：范围徽标、匹配高亮、发送时间、所在会话标题；`Tab` 插入、`Enter` 直接发送（沿用我们现有约定）。
- 去重：同一文本跨会话只显示最新一条，其余折叠为 `+N`。

**成本**：约 120 行（现有浮层 + ring 上扩展）+ 2 条 e2e。
**风险**：低。

---

### 4. Vim 编辑模式（差异化，但受众窄）

**为什么有价值**：Claude Code 与 Codex 都有，市场**零覆盖**，而"终端式输入框"的品牌定位天然适合。
**成本与风险**：400-600 行；需要处理 Lexical contenteditable 的选区/输入法（CJK 组词期间必须直通），
且要提供 `INSERT/NORMAL/VISUAL` 最小集（`h j k l w b e 0 $ i a A I o O x dd cc yy p /`）。
**建议**：作为 v2 级项目，先把 1-3 做完再做。

---

### 5. 大段粘贴折叠（`[粘贴 #1]` 芯片）

**为什么有价值**：Claude Code 的 `[Pasted text #N]` 能避免几千行日志把输入框撑爆；市场无覆盖。
**风险**：中高。芯片必须存在于**宿主的编辑模型**里才能随草稿保存/发送，而我们是外部插件——
上一轮 PR #16 已经证明"拦截发送再改写草稿"极其脆弱。**结论：等技术上可行的宿主钩子，或做成
"折叠标记 + 发送时展开"的纯文本方案**（不引入 DOM 芯片），后者可行但要接受文本里出现标记。

## 4. 建议路线

| 阶段 | 内容 | 预计工作量 |
|---|---|---|
| 下一次发版（1.9） | 草稿历史与找回 + 敏感信息守卫 | 2 个功能，约 450 行 + 5 条 e2e |
| 之后（1.10） | 跨范围搜索 | 约 120 行 |
| 想做差异化时（2.0） | Vim 模式 | 400-600 行 |
| 等宿主能力 | 粘贴折叠（若 DSH 提供输入节点 API） | — |

**共同实现约束（沿用本项目既有原则）**
1. 不触碰宿主的提交路径（`submit`/`insertText` 之外的私有成员一律不碰）。
2. 所有新键位必须让位给 `@`/`/` 原生菜单与输入法组合键。
3. 每个功能都要有 e2e；性能类必须走 `frame.ts` 的单帧合并，不做定时器轮询。
4. 偏好项默认值要保守（草稿快照默认开、敏感信息守卫默认开、Vim 默认关）。

## 5. 附：本次评估顺带发现的两件事

1. **市场元数据过期**：插件市场里我们的描述仍写着"可拖动会话目录（Chat TOC）"，而该功能已在 v1.8.0 移除；
   且市场里存在**两条重复条目**（8066 与 2152 下载）。建议更新描述、合并条目——这是免费的曝光改善。
2. **原生已经很强**：草稿跨刷新保留、轮次导航、steering 排队、附件、`/`+`@` 菜单都已原生具备。
   插件若继续在这些方向加功能，属于和宿主重复；上面的候选全部避开了这些点。
